# skills-creator-workflow

## 何时用

用户输入 `/skills-creator-workflow`，要新建一个 skill 时。

不适用：一次性任务（直接做）；修改已有 skill（不在本流程内）。

## 前置：定根目录

- 默认用当前工作区目录。
- 用户明确指定了别处，就用用户给的。
- 不确定时先问，不要猜。

以下所有 `docs/`、`drafts/`、`releases/` 都相对这个根。

## 第 1 步：问齐需求

一次问完，必答：

1. 这个技能叫什么名字（kebab-case，同时就是目录名）
2. 解决什么问题、什么场景下用
3. 输入是什么、期望输出是什么
4. 有哪些必须遵守的规则或边界
5. 是否需要脚本（PowerShell / Python / bat），脚本负责什么
6. 是否需要 `references/` 或 `assets/`
7. 已知会翻车的地方

**停：**七项都答完，或用户明确说「就这些」「可以了」，才进第 2 步。仍有必答项没答就继续问，不要替用户补全。

## 第 2 步：写需求文档

写 `<根>\docs\<name>.md`，包含八节：

目的 / 使用者与场景 / LLM 角色 / 触发方式 / 工作目录约定 / 目录结构 / 流程与最小试跑集 / 已知坑与范围外

这份文档只写需求与决策，**不写验收清单**——清单只维护在 `SKILL.md` 里，避免两份漂移。

**停：**写完给用户看，等「确认」。用户提意见就改，改完再等确认，不得自行推进。

## 第 3 步：写草稿

1. 建 `<根>\drafts\<name>\`
2. 写 `SKILL.md`：frontmatter 有 `name`（= 目录名，kebab-case）和 `description`（做什么 + 什么时候用）
3. 正文四节：何时用 / 步骤 / gotchas / 完成标准
4. 需要脚本就建 `scripts\`，正文按相对路径引用，基目录是技能目录本身
5. 对照本文末尾「验收清单」逐条打勾，有未打勾的先改

**停：**写完后告知草稿位置和自检结论，等用户查看。

## 第 4 步：跑最小试跑集

写 `<根>\docs\<name>.trial.md`，至少三类用例：

| 类型 | 测什么 |
| --- | --- |
| 正常路径 | 最典型输入能否走完全流程；跑 2 次看行为是否一致 |
| 边界 | 输入极简 / 极繁 / 缺信息时是否会停下来问 |
| 失败路径 | 该拒绝、该停下的场景有没有自作主张 |

规则：

- 用真实材料，不许自己编一个「典型任务」自测
- 有脚本必须真实执行一遍，看退出码
- 每条记：输入 / 期望 / 实际 / 通过与否
- 任一不通过 → 回第 3 步

**停：**把试跑结论连同「局限」一节交给用户，用户认可才进第 5 步。

## 第 5 步：冻结

把 `drafts\<name>\` 整目录复制到 `releases\<name>\`，并校验两边内容一致。

**不要删 `drafts\`**，它是后续迭代的工作副本。

## 第 6 步：询问是否安装到全局

全局路径：`C:\Users\13563\.agents\skills\<name>`

- 不存在 → 问用户是否安装；同意就把 `releases\<name>\` 整目录复制过去
- 已存在 → 停下来，把新旧差异告诉用户，由用户决定覆盖 / 保留 / 中止；不得自行覆盖
- 用户不装 → 流程结束

**停：**安装前必须等用户明确同意。

## 验收清单

写 SKILL.md 时逐条对照，全部打勾才算草稿完成。清单条目必须可观察。

- 反例：`流程清晰`
- 正例：`用户没说「就这些」时，不得进入第 3 步`

- [ ] 目录只有一层 `<name>\SKILL.md`
- [ ] `name` 等于目录名，kebab-case
- [ ] `description` 同时写清做什么、什么时候用
- [ ] 正文包含：何时用 / 步骤 / gotchas / 完成标准
- [ ] 每条 gotcha 写成「什么现象 + 怎么绕开」
- [ ] 每个确认点写明什么条件下必须停
- [ ] 每个阶段的产出都有对应确认点，不存在「成功就自动推进」的步骤
- [ ] 安装前查同名，同名时询问而不是覆盖
- [ ] 正文 ≤ 8192 字符（超了会被 DSH 裁剪，按 8000 留余量），超出的放 `references/`
- [ ] 脚本用相对技能目录的路径引用
- [ ] 脚本有退出码语义、不依赖交互输入、不硬编码绝对路径
- [ ] `.ps1` 提供 `.cmd` 包装或 `-ExecutionPolicy Bypass` 的调用方式

## gotchas

1. **只扫一层**：只有 `<root>\<name>\SKILL.md` 会被发现，嵌套的不认。
2. **name 必须等于目录名**，不一致会导致整个技能被跳过。
3. **正文超 8192 字符会被静默裁剪**，切点不可控，比报错更难查；把细节挪进 `references/` 或压缩正文来规避。
4. **PS 5.1 + Restricted**：`.ps1` 直接跑会被拦，需要 `.cmd` 包装。
5. **`python3` 是 Windows 商店占位程序**，调用没有输出，用 `python` 或 `py`。
6. **全局目录可能不存在**，安装前先建。
7. **在别的项目里调用**会把 `docs/drafts/releases` 写进那个项目，注意别污染别人的仓库。

## 完成标准

- `releases\<name>\SKILL.md` 存在，且验收清单全部打勾
- `docs\<name>.md` 与 `docs\<name>.trial.md` 都存在
- 用户已明确表示是否安装
- 若安装，同名情况已由用户决定
