# 技能需求：skills-creator-workflow

> 状态：待确认（第 2 步产物）
> 创建日期：2026-11-01
> 工作目录：`D:\agentStudy\MyPersonalSkills`

## 1. 目的

把「从想法到能装进全局的 skill」这件事固化成一条可复用的流程，避免每次临时发挥导致结构不一致、漏校验、装错位置。

## 2. 使用者与场景

- 使用者：仓库所有者本人。
- 场景：想到一个新 skill，或发现某个 skill 没被识别。
- 不适用：一次性任务（不建 skill，直接做）；修改已有 skill（不在本流程范围内）。

## 3. LLM 角色

执行者 + 校对者：负责提问澄清、生成文档与文件、逐条对照验收清单自检、执行目录操作。

**不代替用户做取舍判断**——每个确认点必须停下来等人，不许自行跳过。

## 4. 触发方式

- 仅手动：用户输入 `/skills-creator-workflow` 触发。
- 不进入模型自动匹配目录（对应 frontmatter 的 `disable-model-invocation: true`）。
- 理由：建 skill 是低频、需要人主导的操作，自动触发容易在闲聊时被误唤起。

## 5. 工作目录约定

- 默认 = 调用时的工作区目录（会话 cwd）。
- 用户明确指定其他目录时，以用户指定的为准。
- `docs/`、`drafts/`、`releases/` 都落在这个根下。

## 6. 目录结构

```
<根>\
  docs\<skillName>.md          # 需求文档（不含验收清单）
  docs\<skillName>.trial.md    # 试跑记录
  drafts\<skillName>\          # SKILL.md + scripts/ + references/ + assets/
  releases\<skillName>\        # 冻结快照，内容与 drafts 一致
```

- 一个 skill 一个目录，目录名 = skill 名（kebab-case）。
- `releases\` 是唯一会被安装到全局的形态。
- `scripts/`：可执行脚本，PowerShell、Python、bat 都行；随技能目录一起装到全局，正文一律按相对路径引用。
- `references/`：按需读取的长文档；`assets/`：模板、图片等非可执行资源。

## 7. 流程

本流程只覆盖新建 skill。是否该建、要不要复用已有 skill，由你在调用前决定——调用 `/skills-creator-workflow` 就表示已经决定新建。

| 步 | 动作 | 产物 | 卡点 |
| --- | --- | --- | --- |
| 1 | 一次问齐需求（含技能命名） | 需求清单 | 七项没答完且用户没说「就这些」→ 继续问 |
| 2 | 写需求文档 | `docs\<name>.md` | 用户不确认 → 按意见改 |
| 3 | 写草稿 | `drafts\<name>\SKILL.md` 等 | 验收清单有未打勾项 → 改 |
| 4 | 跑最小试跑集 | `docs\<name>.trial.md` | 任一用例不通过 → 回步 3；否则交用户确认试跑结论 |
| 5 | 冻结 | `releases\<name>\` | — |
| 6 | 询问是否装全局 | 安装或结束 | 同名 → 交用户决定 |

### 7.1 最小试跑集

第 4 步不是「随便跑一下」，而是**把 SKILL.md 里验收清单的条目转成用例**。至少覆盖三类：

| 类型 | 测什么 | 判据来源 |
| --- | --- | --- |
| 正常路径 | 最典型的输入能否走完全流程 | 验收清单全部条目 |
| 边界 | 输入极简、极繁或信息缺失时，是否停下来问 | 验收清单「确认点」条目 |
| 失败路径 | 该拒绝、该停下的场景有没有自作主张 | 验收清单「同名询问」条目 |

规则：

- **任务来源优先用真实材料**：刚做完的真实任务 > 从验收清单反推 > 历史 docs 与踩坑记录。不许让模型自己编一个「典型任务」来自测——那是自证循环。
- **输入必须是你真会用的**，输出必须是你真敢拿去用的。
- **正常路径至少跑 2 次**，比对关键行为是否一致（是否都触发、是否停在同一处、产出结构是否同形）。比对行为，不比对逐字输出。
- **失败路径最容易被跳过，必须测**。
- **必须真实走一遍脚本路径**，直接看退出码，不靠肉眼判断输出对不对。
- 每次结果记一行：输入 / 期望（来自哪条验收清单）/ 实际 / 通过与否，写进 `docs\<name>.trial.md`。
- 验收清单只存在于 `SKILL.md` 里，这份需求文档不重复维护。
- 能机械判定的（目录结构、frontmatter、脚本退出码）用命令断言；只有质量类判断交给人看。

## 8. 已知坑

1. **目录嵌套不会被发现**——只认 `<root>\<name>\SKILL.md` 一层。
2. **在别的项目里调用会污染那个项目**——默认写当前工作区，`docs/drafts/releases` 会落进去；这类场景要显式指定根目录。
3. **中文 `description` 的路由命中率**在部分客户端上可能略低于英文，个人使用可接受，别人要用时自行调整文案。
4. **这台机器是 Windows PowerShell 5.1 + `Restricted`**，`.ps1` 直接跑会被拦，需要 `.cmd` 包装或 `-ExecutionPolicy Bypass`。
5. **仓库 `.git` 在当前沙箱模式下不可写**——它的权限列表不继承仓库根，DSH 授予的写权限传不进这一层。`git status`、`git log` 这类只读命令正常；`git add`、`git commit`、`git restore` 会报 `index.lock` 权限拒绝。要把 git 写操作纳入流程，需先把会话切成完全权限。
6. **全局目录可能还不存在**，安装前要先建。
7. **`python3` 在这台机器上是 Windows 商店占位程序**，调用没有任何输出；认 Python 要用 `python` 或 `py`（实测 3.10.7）。
